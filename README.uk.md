# TikTok Clone

[English](README.md) | Українська

Соціальний застосунок для коротких відео на React та ASP.NET Core з окремим сервісом асинхронної обробки відео.

## Можливості

- Головна стрічка та стрічка підписок, відтворення HLS, пошук і посилання для поширення відео.
- Завантаження відео, прогрес обробки та особиста відеостудія.
- Профілі, підписки, вподобання, коментарі й відповіді, обране та репости.
- Особисті повідомлення, приватність листування та сповіщення в реальному часі.
- Вхід через Google або пошту й пароль, підтвердження пошти, відновлення пароля та керування сеансами.
- Скарги на вміст, модерація адміністраторами, українська й англійська локалізації.

## Архітектура

| Каталог | Призначення |
| --- | --- |
| `front/` | React 19, TypeScript, Vite, Tailwind CSS, Redux Toolkit / RTK Query, i18next |
| `back/Api/` | HTTP API на .NET 10, автентифікація, Swagger, SignalR |
| `back/Application/`, `back/Domain/`, `back/Contracts/` | Логіка застосунку, доменні сутності, спільні контракти |
| `back/Infrastructure/`, `back/Persistence/` | Інтеграції, EF Core, PostgreSQL, міграції бази даних |
| `back/VideoProcessor/` | Обробка відео через FFmpeg із RabbitMQ / MassTransit |
| `back/Application.Tests/` | Тести логіки бекенду |
| `tools/` | Конфігурація Jenkins, Terraform і розгортання |

PostgreSQL зберігає дані, Redis забезпечує кешування, а RabbitMQ з'єднує API з обробником відео. SignalR передає повідомлення чату, сповіщення та оновлення обробки. У режимі розробки медіафайли зберігаються локально у спільному сховищі, у production — в Amazon S3.

## Локальний запуск через Docker

Встановіть Docker із плагіном Compose. У корені репозиторію виконайте:

```bash
docker compose -f compose.local.yaml up --build -d
```

Команда запускає фронтенд, API, обробник відео, PostgreSQL, Redis і RabbitMQ. Перша збірка завантажує залежності й може тривати кілька хвилин. API автоматично застосовує міграції та створює тестових користувачів із `back/Api/Helpers/Users.json`. Підготовлені початкові відео можна розмістити в `back/Api/SeedVideos/`.

| Сервіс | Адреса |
| --- | --- |
| Вебзастосунок | http://localhost |
| Перевірка доступності API | http://localhost:8080/health |
| Swagger UI (розробка) | http://localhost:8080/swagger |
| Керування RabbitMQ | http://localhost:15672 (`guest` / `guest`) |
| PostgreSQL | `localhost:5432` |
| Redis | `localhost:6379` |

Локальні облікові дані PostgreSQL: `postgres` / `mypassword`, база `tiktok_clone`. Пароль Redis — `localredispass`. Ці значення визначені в `compose.local.yaml` для локальної розробки.

Для входу через Google задайте `GOOGLE_CLIENT_ID` і `GOOGLE_CLIENT_SECRET` у кореневому `.env` та зареєструйте адресу фронтенду в Google. Для надсилання листів потрібні `SMTP_PASSWORD` і налаштування секції `SMTP` API відповідно до провайдера (хост, порт, ім'я користувача). Значення-заглушки не забезпечують роботу цих інтеграцій. Локальний стек не потребує облікових даних AWS.

```bash
docker compose -f compose.local.yaml logs -f api video_processor
docker compose -f compose.local.yaml down
```

`down` зберігає іменовані томи, зокрема базу даних і завантажені медіафайли. Додавання `-v` видаляє ці томи.

## Розробка фронтенду

Використовуйте Node.js 22 та npm, як у Docker-збірці фронтенду. Залиште Docker-сервіси бекенду запущеними та створіть `front/.env`:

```dotenv
VITE_API_BASE_URL=http://localhost:8080
VITE_GOOGLE_CLIENT_ID=your-google-client-id
```

```bash
cd front
npm ci
npm run dev
```

Відкрийте адресу, яку виведе Vite, зазвичай http://localhost:5173. Для входу через Google зареєструйте також цю адресу. Значення з префіксом `VITE_` потрапляють у браузерну збірку: не зберігайте в них секрети. Після їх зміни перезапустіть Vite або перебудуйте Docker-образ фронтенду.

## Розробка бекенду

Для збірки та запуску бекенду поза Docker встановіть .NET 10 SDK. Кожен сервіс має `appsettings.Development.json`; змінні середовища перевизначають налаштування через подвійне підкреслення, наприклад `ConnectionStrings__DefaultConnection`.

Для розробки на хості зупиніть Docker-контейнери API й обробника, щоб уникнути конфліктів портів і конкуруючих споживачів черги; залиште `db`, `redis` та `rabbitMQ` запущеними. Використовуйте профіль API `http` (порт 8080), задайте `DOTNET_ENVIRONMENT=Development` для обробника та однаковий абсолютний `LocalStorage__RootPath` для обох сервісів. Для API задайте `Redis__ConnectionString=localhost:6379,password=localredispass`. Якщо використовуєте Vite, задайте `Frontend__Url=http://localhost:5173`, щоб посилання відновлення пароля вели на потрібний фронтенд.

Обробник потребує FFmpeg. Його Docker-образ встановлює FFmpeg; у режимі розробки код запуску також намагається завантажити виконувані файли до тимчасового каталогу. Якщо обробка не працює, перегляньте журнали обробника та перевірте доступність цих файлів. Для ручного встановлення додайте FFmpeg і FFprobe до `PATH` та перевірте `ffmpeg -version` і `ffprobe -version`.

## Перевірки та локалізація

У каталозі `front/`:

```bash
npm run check:locales
npm run lint
npm run build
```

У корені репозиторію:

```bash
dotnet test back/Application.Tests/Application.Tests.csproj
```

Переклади розміщені у `front/src/locales/en/en.json` та `front/src/locales/uk/uk.json`. Додавайте ключі до обох файлів і зберігайте змінні інтерполяції, наприклад `{{count}}`. Перевірка локалізацій порівнює вкладені ключі, типи значень і змінні інтерполяції. Визначення мови та резервну англійську локалізацію налаштовано у `front/src/i18n.ts`.

## Розгортання

`compose.server.yaml` — основа, яка потребує налаштування під ваше середовище. Використовуйте `.env_server_example` як перелік змінних та явно передавайте налаштований файл через `--env-file .env_server`. Перевірте `front/nginx.server.conf` (домен і шляхи TLS-сертифікатів), production-налаштування API, бакет, регіон та облікові дані S3, SMTP, базу даних, Redis, RabbitMQ і JWT.

Створення адміністратора в production використовує `AdminAccount__Login` та `AdminAccount__Password`. Передайте обидві змінні через секцію середовища сервісу API в Compose: додавання змінних лише до `.env` не передає їх контейнерам. Назву `AdminAccount_Password` у прикладі потрібно записати з подвійним підкресленням для .NET.

Не зберігайте секрети в репозиторії, розмістіть TLS-сертифікати за налаштованими шляхами в `certbot/` та перевірте відкриті порти й конфігурацію резервного копіювання для свого середовища.
